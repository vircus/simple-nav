## 1. 产品概述

### 1.1 一句话定位

一个部署在自有域名下的**个人/团队主页工具导航站**：既是浏览器起始页，汇集常用互联网工具；也是导航中枢，统一入口到本域名的各个二级域名站点与外部优质链接，并提供后台管理面板完成全站配置。

### 1.2 核心价值

| 价值点 | 说明 |
| --- | --- |
| 统一入口 | 一个主页承载「自有二级域名站点 + 外部常用链接 + 内置工具」三类资源 |
| 开箱即用 | 内置高频互联网工具，切换即用，无需跳转第三方 |
| 自助可控 | 管理面板支持增删改查与站点级设置 |
| 愉悦体验 | 多巴胺风格视觉与微交互贯穿全站，让高频工具站具备情绪价值 |
| 零成本运维 | Serverless 架构，免服务器、免备案即可上线 |

### 1.3 目标用户

- **主要用户**：站点拥有者本人，日常用作浏览器首页或个人工作台。
- **次要用户**：被授权访问的团队成员或访客，浏览导航与使用内置工具。
- **管理者**：站点拥有者，通过隐藏路径进入管理面板。

### 1.4 非目标（Out of Scope）

- 多用户注册、登录、收藏同步（仅单管理员）
- 公开的用户投稿 / 链接推荐审核流
- 搜索聚合、爬虫抓取外部站点元数据
- 广告位、商业化、数据看板与访问统计报表
- 浏览器插件 / 移动 App

### 3.6 服务端 API 契约（草案）

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/site-data` | 公开 | 分类 + 站点 + 已启用工具 + 站点设置 |
| GET | `/api/tools/proxy` | 公开 | 网络查询工具**服务端代理**，保护 Token 不下发浏览器 |
| POST | `/api/admin/login` | 公开 | 校验密码，签发会话 |
| POST | `/api/admin/logout` | 管理员 | 清除会话 |
| GET | `/api/admin/data` | 管理员 | 含禁用项的完整数据 |
| PUT | `/api/admin/categories` | 管理员 | 全量覆盖（含排序） |
| PUT | `/api/admin/sites` | 管理员 | 全量覆盖（含排序） |
| PUT | `/api/admin/tools` | 管理员 | 启用状态与排序 |
| PUT | `/api/admin/settings` | 管理员 | 站点设置（含主域名、网络服务） |

**设计说明：** 写接口采用**全量覆盖**而非单条增删改。一是排序本质为列表级操作，全量提交语义更清晰；二是减少 API 数量与 KV 读写次数，降低最终一致性带来的中间态问题。

### 3.7 视觉与交互设计规范

#### 3.7.1 设计基调

**绿白灰（Green / White / Grey）**：以绿色为唯一强调色相，白色与灰色承担底与层次。整体克制、清晰，适合长时间高频使用。

三条约束：

1. **强调色只在绿色梯度内变化**：靠明度与深浅区分，不引入其他色相。
2. **红色仅作语义错误态**：`coral` 专用于校验失败与危险操作，**不参与装饰性轮转**。
3. **正文可读性优先**：正文对比度 ≥ 4.5:1；渐变只用于品牌块与主 CTA。

#### 3.7.2 色彩令牌

| 令牌 | 色值 | 用途 |
| --- | --- | --- |
| Brand | `#15803D` | 主绿：文字强调、图标、主 CTA |
| Accent | `#059669` | 翠绿：渐变终点、次要强调 |
| Solar | `#79B291` | 灰绿：浅色徽标与描边 |
| Pop | `#107A57` | 墨绿：成功态、进度 |
| Flash | `#64746E` | 中性灰：辅助信息、表格 |
| Coral | `#B91C1C` | **语义错误色**，不参与轮转 |

中性层——浅色模式：底 `#F6FAF7`、面 `#FFFFFF`、边框 `#E2E8E4`；深色模式：底 `#0B0F0D`、面 `#141A17`、边框 `#2A3531`。

分类标识按索引在**绿色梯度内轮转**（已排除 coral），保证节律一致且不偏离主色系。

#### 3.7.3 排版

- 显示字重 **800–900**，字距收紧至 `-0.02em ~ -0.04em`。
- Hero 标题：移动端 ≥ `2.5rem`，桌面端 ≥ `4rem`，渐变文字 + 紧字距。
- 字体栈：`Inter` → `HarmonyOS Sans SC` → `PingFang SC` → `Microsoft YaHei` → `system-ui`。**不引入构建期网络字体依赖**（`next/font/google` 需在构建期访问 Google Fonts，若 EdgeOne 构建环境网络受限会直接导致构建失败）。
- 数字与代码使用等宽字体栈；字阶移动端 1.25、桌面端 1.333。

#### 3.7.4 微交互清单

| 编号 | 交互 | 触发 | 说明 |
| --- | --- | --- | --- |
| MI-1 | 跟随式光标光晕 | 指针移动 | 桌面端径向渐变跟随，半径 ~200px，`pointer-events:none` |
| MI-2 | 卡片聚光灯 | 悬停 | 光斑跟随指针，仅在卡片内可见 |
| MI-3 | 磁吸微位移 | 悬停 | 卡片随指针方向偏移 ≤ 6px |
| MI-4 | 分层入场 | 首屏加载 | 元素按 60ms 递进淡入上移 |
| MI-5 | 悬停抬升 | 悬停 | `translateY -4px` + 阴影加深 + 渐变描边显现 |
| MI-6 | 按压回弹 | 按下 | `scale 0.97 → 1`，回弹缓动 |
| MI-7 | 渐变流光 | 常驻 | 品牌标识与主 CTA 背景渐变位移 |
| MI-8 | 涟漪反馈 | 点击 | 从点击位置扩散圆形 |
| MI-9 | 滚动揭示 | 进入视口 | IntersectionObserver 触发淡入上移 |
| MI-10 | 数字滚动 | 数值变化 | 统计值过渡 |
| MI-11 | 骨架微光 | 加载态 | shimmer 扫描 |

#### 3.7.5 动效原则

| 项 | 规定 |
| --- | --- |
| 时长 | 微交互 120–200ms；入场 300–500ms；页面级 400–600ms |
| 缓动 | 默认 `cubic-bezier(0.22, 1, 0.36, 1)`；回弹 `cubic-bezier(0.34, 1.56, 0.64, 1)` |
| 性能 | 仅动 `transform` / `opacity` / `filter`；**禁止**动画 `width`/`height`/`top`/`left` |
| 降级 | `prefers-reduced-motion: reduce` 时关闭位移与光晕，仅保留 opacity 淡入 |
| 移动端 | 关闭跟随光标与聚光灯（无 hover 语义），改用按压反馈 |
| 并发 | 单屏同时运行动画的元素 ≤ 8 个 |

#### 3.7.6 视觉资产

- **图标**：lucide 线性图标，统一描边。
- **站点图标**：优先抓取目标 favicon；失败降级为品牌色渐变块 + 首字母。
- **插画**：几何渐变图形，不依赖位图。
- **圆角**：卡片 `16–20px`，按钮 `999px`，输入框 `12px`。
- **阴影**：分层柔和阴影；深色模式改用边框光替代阴影。

## 4. 数据模型

KV 单命名空间，按 Key 分区：

| Key | 内容 | 预估 |
| --- | --- | --- |
| `nav:categories` | 分类数组 | < 5 KB |
| `nav:sites` | 站点数组 | < 100 KB |
| `nav:tools` | 工具配置数组 | < 5 KB |
| `nav:settings` | 站点设置（含主域名、网络服务） | < 10 KB |

**KV 限制（免费版）：** 命名空间 1 GB、单 Value ≤ 1 MB、最多 10 个命名空间。站点数超过约 3000 条时需改用分片 Key。

### 4.1 数据结构定义

```ts
interface Category {
  id: string;
  name: string;
  icon?: string;
  order: number;       // 升序
}

interface Site {
  id: string;
  categoryId: string;
  name: string;
  url: string;         // 必须以 http(s):// 开头
  icon?: string;
  description?: string;
  isInternal: boolean; // 是否本站二级域名
  openInNewTab: boolean;
  order: number;
}

interface ToolConfig {
  slug: string;
  enabled: boolean;
  order: number;
}

interface NetworkServiceConfig {
  enabled: boolean;
  endpoint: string;          // 支持 {ip} / {domain} / {type} 占位符
  method: 'GET' | 'POST';
  headers?: string;          // 自定义请求头，JSON 字符串
  token?: string;            // 鉴权 Token（仅服务端使用，不下发浏览器）
  tokenPlacement: 'none' | 'header' | 'query';
  tokenKey: string;
  timeoutMs: number;         // 默认 8000
  cacheTtlSec: number;       // 默认 300，服务端内存缓存
}

interface SiteSettings {
  title: string;
  subtitle?: string;
  logoUrl?: string;
  faviconUrl?: string;
  themeColor: string;
  defaultTheme: 'light' | 'dark' | 'system';
  footerText?: string;

  // 主域名（v1.1）：唯一用途是识别站点链接是否为本站二级域名，
  // 据此展示「本站」徽标。不参与任何路由、跳转、鉴权或 Cookie 逻辑。
  primaryDomain?: string;

  network?: {
    ipLookup: NetworkServiceConfig;
    dnsLookup: NetworkServiceConfig;
  };

  seo: {
    title?: string;
    description?: string;
    keywords?: string;
    ogImage?: string;
  };
}
```

### 4.2 主域名识别规则

```
hostname = new URL(url).hostname
若 hostname === primaryDomain 或 hostname.endsWith("." + primaryDomain)
  → isInternal = true，展示「本站」徽标
否则 → false
```

该判断**仅影响徽标展示**，不改变链接跳转行为。`primaryDomain` 为空时关闭识别。

## 5. 技术架构

### 5.1 技术选型

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Next.js 15+（App Router） | EdgeOne 支持 13.5+ / 14 / 15 / 16 |
| 语言 | TypeScript | 类型安全 |
| 样式 | Tailwind CSS | 设计令牌与响应式断点 |
| 组件 | 自建轻量组件 | 无重型依赖 |
| 拖拽 | 原生 HTML5 Drag & Drop | 避免额外依赖 |
| 图标 | lucide-react | tree-shakeable |
| 二维码 | qrcode | 浏览器端生成 |
| 存储 | EdgeOne KV | 1 GB 免费额度 |
| 部署 | EdgeOne Pages（Git 集成） | 推送自动构建 |

### 5.2 关键架构决策

**决策一：SSR 而非静态导出。** 管理面板需运行时写入 KV，静态导出无服务端运行时；改用「静态文件 + 重新部署」则每次保存需等 1–2 分钟构建。

*约束：* Next.js 原生 `rewrites`/`redirects` 在 EdgeOne **不受支持**，须改用 `edgeone.json`；根目录 `.nvmrc` 可能导致构建失败；无持久化文件系统；函数默认超时 30s（可配至 120s）。

**决策二：KV 最终一致性处理。** 全球同步最长约 60 秒。应对：① 前端乐观更新；② Toast 提示同步窗口；③ 禁止"保存后立即回读校验"；④ 写入串行化。

**决策三：鉴权。** 单管理员密码 + HMAC 签名 `httpOnly` Cookie，密码哈希存环境变量，`/api/admin/*` 在 Middleware 统一校验。

> **安全提示**：适用于个人站点。若开放多用户，应迁移至正式认证服务。

**决策四：工具前端化。** 本地计算在浏览器执行，除隐私考量外可**规避边缘函数配额消耗**（300 万次/月、300 万 ms/月）。

**决策五：网络查询走服务端代理。** 用户在后台可填带 Token 的接口。为**防止 Token 泄露到浏览器**，含 Token 的请求统一经 `/api/tools/proxy` 转发：浏览器只见工具标识与查询参数；服务端读 KV 配置拼接请求并注入凭证；结果按 `cacheTtlSec` 内存缓存。未配置 Token 时由浏览器直连公开接口，减少一次往返。

### 5.4 环境变量清单

| 变量名 | 必需 | 说明 |
| --- | --- | --- |
| `ADMIN_USERNAME` | 是 | 管理员账号（默认 `admin`） |
| `ADMIN_PASSWORD` | 是* | 明文密码；配置 `ADMIN_PASSWORD_HASH` 时可省略 |
| `ADMIN_PASSWORD_HASH` | 否* | 密码哈希，**配置后优先于明文**（生产推荐） |
| `SESSION_SECRET` | 是 | 会话签名密钥（≥32 位随机串） |
| `SITE_DOMAIN` | 否 | 主域名**初始默认值**。正式配置在管理面板维护，此处仅作首次部署兜底 |

> EdgeOne 限制：变量名 ≤255 字节，变量值 ≤500 字节。

### 5.5 KV 绑定

控制台创建命名空间（如 `nav-store`），项目「KV 存储」中绑定，变量名 `NAV_KV`。

### 5.6 管理入口与鉴权

管理面板位于**常规路径 `/admin`**，不做路径隐藏（v1.2 调整）。

| 规则 | 行为 |
| --- | --- |
| 访问 `/admin/*` | 有有效会话则正常渲染 |
| 未登录访问 | 重定向至 `/admin/login` |
| `/api/admin/*`（除 login） | 无有效会话返回 401 |
| 前台导航与页脚 | 不渲染管理入口链接 |
| `robots.txt` | `Disallow: /admin`、`/api/` |
| 管理页 meta | `noindex, nofollow` |

**凭据来源**：账号与密码均由环境变量提供——

| 变量 | 说明 |
| --- | --- |
| `ADMIN_USERNAME` | 管理员账号（默认 `admin`） |
| `ADMIN_PASSWORD` | 明文密码 |
| `ADMIN_PASSWORD_HASH` | 可选；配置后**优先**于明文做哈希比对（生产推荐） |

**安全边界**：路径公开意味着入口可被发现，因此**防线全部落在凭据强度与会话校验**上——密码哈希存储、HMAC 签名 `httpOnly` Cookie、登录限流（同 IP 连续失败 5 次锁定 15 分钟）。生产环境必须使用强密码，并优先配置 `ADMIN_PASSWORD_HASH`。

## 7. 部署方案（EdgeOne Pages）

### 7.1 部署流程

1. 代码推送至 GitHub / GitLab。
2. EdgeOne 控制台 → Pages → 创建项目并关联仓库。
3. 构建设置：Framework = Next.js；构建命令 `npm run build`；输出目录 `.next`。
4. 环境变量填 `ADMIN_PASSWORD_HASH`、`SESSION_SECRET`、`ADMIN_PATH`。
5. 创建 KV 命名空间并绑定（`NAV_KV`）。
6. 触发构建，获得 `*.edgeone.app` 预览域名。
7. 绑定自有主域名：TXT 验证 → CNAME 指向平台 → 生效 → 申请免费 SSL。
8. 首次登录后，在「站点设置 → 主域名」填入主域名（正式配置来源）。

### 7.2 注意事项

- **中国大陆访问**：加速区域选「全球（不含中国大陆）」时国内返回 401，且预览域名有有效期。国内访问需切换加速区域并完成 ICP 备案。
- **域名数量**：单项目 ≤20 个域名，单账号 ≤40 个项目。二级域名站点为**独立项目**，各自绑定子域名。
- **构建前检查**：确认根目录无 `.nvmrc` 或版本兼容。
- **缓存**：静态资源长缓存 + 内容哈希；`/api/*` 禁止缓存。
- **回滚**：部署历史一键回滚。

### 7.3 多站点拓扑

```
              example.com  （导航站主站 · 本项目）
                    │
    ┌───────────────┼───────────────┐
    │               │               │
blog.example.com  tools.example.com  wiki.example.com
  （独立项目）       （独立项目）        （独立项目）
    └───── 主站通过 primaryDomain 识别并标注「本站」 ─────┘
```

## 10. 风险登记

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| KV 最终一致性读到旧数据 | 管理体验下降 | 乐观更新 + 同步窗口提示 + 写入串行化 |
| `rewrites`/`redirects` 不受支持 | 路由受限 | 统一改用 `edgeone.json` |
| `.nvmrc` 导致构建失败 | 无法部署 | 部署前删除或调整版本 |
| 管理密码泄露 | 数据被篡改 | 强密码 + 哈希存储 + 登录限流；生产环境优先 `ADMIN_PASSWORD_HASH` |
| 公开路径被扫描 | 暴力破解风险 | 入口公开属预期，故依赖限流与强凭据；不在路径上做安全性假设 |
| 第三方接口不稳定或超额 | 网络工具不可用 | 后台可换接口；服务端缓存降频；失败明确降级提示 |
| 高饱和配色影响可读性 | 可读性下降 | 色相数量约束 + 对比度硬指标 + 渐变不用于正文底 |
| 动效过多导致低端设备掉帧 | 体验劣化 | 仅动 transform/opacity/filter；并发 ≤8；尊重 reduced-motion |
| 免费版商业化后配额调整 | 成本上升 | 使用率控制在 10% 以内，保留迁移弹性 |
